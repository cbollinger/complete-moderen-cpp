* Classes & Objects

** Object Oriented Programming Basics
- Uses objects as fundamental building blocks, rahter algorithms
- Program is created as a collection of objects
- Every object is an instance of some class
- Classes are united via inheritance relationship
- Simulate interactions of objects in real-world systems
- Allows representation of objects in problem domain as software objects
- Decreases complexity of software systems
- Make code reusable, extensible and maintanable

*** Object Model
- Basic principles that help us write OO programs
  - Abstraction
  - Encapsulation
  - Inheritance
  - Polymorphism

*** Abstraction (OOSC: Modularity/Decomposability)
- Abstraction focuses on important & necessary details
- Unwanted features are left out
- e.g. name of a person without other details (age, weight, etc)
- Helps focus on important charachteristics
- Used to represent real-life objects in software, but without the association complexity
- Represented through a *class, *struct*, *interface*, *union* or *enum*
 
*** Encapsulation (OOSC: Information Hiding)
- Next step after abstraction
- Hides the implementation details of a class
- The class provides behaviour without revealing the implementation
- Objects of such classes are easy to use
- The internal implementation can be changed without the users knowlege
- implementation through access modifiers in OO langunage

- *Encapsulation* is the mechanism of bundling data and methods into
  a single unit (like a class).

- *Information hiding* is the design goal of concealing the internal
  implementation details of an object so that clients can only
  interact with it through a controlled interfac
  
*** Inheritance
- Represnts a hirachy of classes
- The classes are relatate through *"is-" relationship*
- The relation is due to same behaviour of classes
- *e.g. a dog is an animal*
- The behaviour % its implementation is inherited by the children from
  the parent
- The child classes may then reuse the behaviour with the same
  implementation or provide a different implementation
- Promotes reuse & extensibility

*** Composition
- Signifies relationship between objects
- Represented as *"has-a or "part-of" relationship*
- Promotes reuse of objects
- *e.g. car has en engine* 

*** Polymorphism
- Means different forms
- Represents common behaviour with different implementations
- Response will be different for each object, either based on its
  class or the arguments
- e.g. car, cycle, person, etc. can move differently
- Implemented through function overloading, templates & virtual functions
- Used in conjunction with inheritance & composition
- Promotes reuse, scalability & extensibility

** Constructor & Destructor
- Invoked automatically during instantiation
- Used for initialization
- Doe's not have any return type
- Can be overloaded
  - Default
  - Paramterized
  - Copy
  - Delegation
  - Inheriting

*** Default Constructor
- Constructor with no arguments
  - /Car c;/ invokes default constructor
- Automatically sythsized by the compiler
  - if no other user-defined constructor exist

*** Parameterized Constructor
- Constructor that accepts one or more arguments
- Used to initialize the object with user-defined values
- Never synthsized by the compiler
- Blocks auto generation of default constructor
- 

*** Destructor
- Function that is invoked automatically when an object is destroyed
- Used for releasing resources that may have been allocated in the constructor
- Cannot be overloaded
- No arguments
- Compiler will sythesize one

** Structure

- Create user-defined type through keyword /struct/
- Similar to a class
- Default acces is /public/
- Frequently used
  - to repesent simple abstract types such as point, vector3D, etc.
  - for implementing *function Objects*, used as *callbacs"k in std
    template library

#+LATEX: \captionof{listing}{Struct Point}
#+BEGIN_SRC C++ :flags "-std=c++17 -Wall -Wextra -fno-elide-constructors" :results output verbatim
#include <iostream>

struct Point {
    int x;
    int y;
};

void DrawLine(Point start, Point end) {

    using namespace std;

    cout << __func__ <<"()"<< endl;
    cout << " - Start Point:" << " X=" << start.x << " Y=" << start.x << endl;
    cout << " - End Point:  " << " X=" << end.x   << " Y=" << end.x << endl;
}

int main() {

    Point start;
    start.x = 2;
    start.y = 3;

    Point end;
    end.x = 2;
    end.y = 3;

    DrawLine(start, end);
    
    return 0;
}
#+END_SRC

*** Copy Constructor - Part II

- Creates copy of the object's state in another object
- Synthesized automatically
- Default implementation copies values
- User-defined implementation required for pointer members

#+LATEX: \captionof{listing}{Integer Class - }
#+BEGIN_SRC C++ :flags "-std=c++17 -Wall -Wextra -fno-elide-constructors" :results output verbatim
  #include <iostream>

  //--------------------------------------------------------------------
  // Class Declaration
  //--------------------------------------------------------------------
  class Integer {
      int *m_pInt;

  public:
      Integer();
      Integer(int value);
      Integer(const Integer& obj);  // Copy Constructor, copy by value
      int GetValue() const;
      void SetValue(int value);

      ~Integer();
  };
        
  //--------------------------------------------------------------------
  // Class Definition
  //--------------------------------------------------------------------
  Integer::Integer() {  m_pInt = new int(0);}
  Integer::Integer(int value) {m_pInt = new int(value);}
  Integer::~Integer() {delete m_pInt;}
  //copy constructor - Deep Copy
  //Reference avoids loop of shallow copy
  Integer::Integer(const Integer& obj) {m_pInt = new int(*obj.m_pInt);} 
  int Integer::GetValue() const {return *m_pInt;}
  void Integer::SetValue(int value) {*m_pInt = value;}


  //--------------------------------------------------------------------
  // Test Program
  //--------------------------------------------------------------------
  using namespace std;

  int main() {

      int *p1 = new int(5);
      // Shallow Copy - Copies only the pointer address
      int *p2 = p1;
      // Deep Copy - Copies the value at the address of the pointer
      int *p3 = new int(*p1);

      // mark the pointers as used!
      (void)p1;
      (void)p2;
      (void)p3;

      Integer i  {5};
      Integer i2 {i};      // call copy constructor
      cout << i.GetValue() << endl;
      cout << i2.GetValue() << endl;
                
      return 0;
  }

#+ATTR_LATEX: :options {Rule Of 3}
#+BEGIN_infobox
- All should be defined if a user implements any of them
  - Destructor
  - Copy Constructor
  - Copy assignment operator

- This will be due to allocation of some resources in a constructor
  - Destructor will free the resource
  - Copy constructor will perform a *deep copy*
  - Copy assignment operation will also perform a *deep copy*

- Not Implementing user defined operations can lead to memory leak or shallow copy!
#+END_infobox
