** L-values, R-values & R-value References (C++11)


#+ATTR_LATEX:  :align p{8cm} p{8cm}
| <40>                                              | <40>                                                    |
| *L-Value*                                           | *R-Value*                                               |
|---------------------------------------------------+---------------------------------------------------------|
| Has a name                                        | Does not have a name                                    |
| All variables are L-Values                        | R-value is a temporary value                            |
| Can be assigend values                            | Cannot be assigned values                               |
| Some expressions return l-values                  | Some expressions return r-value                         |
| L-value persists beyond the expression            | Does not persist beyond the expression                  |
| Functions that return by reference return l-value | Functions that return by value return r-value           |
| Reference to l-value (called l-value reference)   | R-value reference to r-value (called r-value reference) |
|                                                   |                                                         |

*R-Value References (C++11)*
- A reference created to a temporary
- Represents a temporary
- Created with && operator (R-value reference operator)
- Cannot point to l-values
- R-value references always bind to temporaries
- L-value references always bind to l-values

#+ATTR_LATEX: :options {R Value References}
#+BEGIN_infobox
int &&r1 = 10;          //R-value reference \\
int &&r2 = Add(5,8);    //Add returns by value (temporary) \\
int &&r3 = 7+2;         //Expression return a temporary 
#+END_infobox

** Move Semantics - Basics (C++11)
- Copy is implemented through copy constructor
- Copy of the object state is created
- Wasteful in case copy is created from a temporary
- Instead, the state can be moved from the source object
- Implemented through move semantics


** Move Semantics - Implementation (C++11)

#+BEGIN_infobox
NRVO: Named Return Value Optimization.

It’s a specific compiler optimization in C++ where a named local
variable returned from a function is constructed directly in the
caller’s return slot, avoiding a copy or move.

    using namespace std;

    class Integer {

    public:
        Integer() {                                              // default constructor
        cout << "Integer()" << endl;
        m_pInt = new int(0);
        }
        Integer(int value) {                                     // parameterized constructor
        cout << "Integer(int)" << endl;

      temp.SetValue(a.GetValue() + b.GetValue());

** Rule of Five
*** Resource Management
- Some classes own a resource
- This resource may be a poiner, file handle, socket etc.
- Such resources may be aquired in the constructor
- Subsenquently, you have to decide the action in case objects of such
  classes are copied, moved or destroyed
- e.g. on destruction, the resource must be released to avoid *leaks#
- Similarly, on copy or move the resource must be handled accordingly

*** Rule of Five
- Consequently, you should implement the rule of 5 for such classes
- If a class has ownership semantics, then you must provide a user-defined
  - Destructor
  - Copy constructor
  - Copy assignment operator
  - Move constructor
  - Move assignment operator
- This is to ensure proper handling of the underlying resource

*** Rule of Yero 
- If a class does not have ownership semantics, then do not provide
  any user defined function from the rule of 5.
- This way the compiler will automatically synthesize the necessary functions
- Providing user-defined implementation of some functions will prevent
  the compiler from synthesizing others
