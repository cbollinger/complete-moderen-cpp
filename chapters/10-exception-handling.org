* Exception Handling

** Basic Exception Handling - Part I

*Exception Handling*
- Mechanism to handle errors in programs that occur at runtime
- These errors are called exceptions
- Exist outside the normal functioning of the program
- Require immediate handling by the program
- If not handled, the program crashes
- Cannot be ignored, unlike C error handling
  
#+LATEX: \captionof{listing}{C-Error Handling}

*Mechanism*

- *try*
  - creates a scope/block & exception causing code appears here
  - can contain other try-catch statements

- *throw*
  - throws an exception from the try block
  - exception is object that is constructed in throw statements

- *catch*
  - handler that catches the exception object
  - should appear just after the try block
  - multiple catch blocks can exist

#+ATTR_LATEX: :options {Stack Unwinding}
#+BEGIN_infobox
Stack unwinding will destroy only local objects. If any objects have
been created on the heap, they will not be destroyed and infact the
memory can be leaked.
#+END_infobox

** Basic Exception Handling - Part IV (Nested Exceptions)


#+LATEX: \captionof{listing}{Exception Handler - Nested Exceptions}
#+BEGIN_SRC C++ :exports both :flags "-std=c++17 -Wall -Wextra -fno-elide-constructors" :results output verbatim
#include <iostream>
#include <limits>
#include <memory>
#include <vector>
#include <random>

using namespace std;

class Test {
public: 
    Test() {cout << "Test(): Acquire resources" << endl;};
    ~Test() {cout << "~Test(): Release resources" << endl;};
};

void ProcessRecords(int count) {
    vector<int> pArray;
    p.reserve(count);    // throws an exception of type bad_alloc
    for(int i=0; i<count; ++i) {
        pArray.push_back(i);
    }
    default_random_engine eng;
    bernoulli_distribution dist;
    int errors {};
    for(const auto & element : pArray) {
        try {
            cout << "Processing record #: "<< element;
            if(!dist(eng)) {
                ++errors;
                throw runtime_error("Could not process the record");
            }
            cout << endl;
        }
        catch (runtime_error &ex) {
            cout << " [ERROR " << ex.what() << "]" << endl;
            if(errors > 3) {
                runtime_error err("Too many errors. Abandoning operation");
                ex = err;
                throw; // rethrow exception
            }
        }
    }
    cout << endl;
}

int main() {

    try {
        // ProcessRecords(numeric_limits<int>::max());
        ProcessRecords(19);
    }
    catch(exception &ex) {
        cout << ex.what() << endl;
    }
    return 0;
}
#+END_SRC

Processing record #: 6
Processing record #: 7 [ERROR Could not process the record]

#include <random>

    A() {cout << "A()" << endl;}

};
class B{
public:
    B() {cout << "B()" << endl;}
    ~B() {cout << "~B()" << endl;}
};

    A *pA{};
    B b{};      // calls destructor when exception

    char *pStr{};
    int *pArr{};

    pInt = new int;

    };

    delete pInt;

    };

    try {

#+ATTR_LATEX: :options {Destructor}
#+BEGIN_infobox
Destructor should not throw an exception. Exception within destructor
may lead to stack unwinding.  If a destructor needs to throw an
exception, than the exception shall be handled within the destructor.
#+END_infobox


** Basic Exception Handling - Part VI (noexcept keyword)

*noexcept*
- Applied to functions (both in declaration & definition)
- Indicates the function does not throw exceptions
- Compiler can optimize the function code
  - no need to generate stack unwinding code
- An exception from such function terminates the program
  - stack may or may not be unwinded
- Not all functions should use noexcept specifier
  - especially functions calling other functions (in library)
  - such functions will be exception-neutral
